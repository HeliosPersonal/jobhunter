Why the ceiling is trustworthy

Priced pessimistically, checked before the call

The cache discount is applied at retrieval time, so the ceiling prices pessimistically at full input — the worst-case matching cost lands near $0.44. CostAccountant.Estimate prices the actually-rendered prompt with the batch discount and writes an Estimated ledger entry before SubmitAsync. If the sum of actuals plus outstanding estimates would exceed ceiling_usd, the client is never called — the Run becomes CostAborted and a reduced digest still ships.

This is invariant 6, and the test for it asserts the LLM client is never called when the ceiling would be breached. A weekly opt-in live test (LiveAnthropicCostAndCacheTests, gated on ANTHROPIC_API_KEY) submits a 20-item matching batch and asserts a >90% cache-hit rate, pricing it through the same CostAccountant.

Чому стелі можна довіряти

Оцінено песимістично, перевірено перед викликом

Знижка кешу застосовується при отриманні, тож стеля оцінює песимістично за повним входом — найгірша вартість matching біля $0.44. CostAccountant.Estimate оцінює фактично зрендерений prompt зі знижкою batch і пише запис Estimated у реєстр перед SubmitAsync. Якщо сума фактичних плюс невиконаних оцінок перевищить ceiling_usd, клієнт не викликається — Run стає CostAborted, а скорочений дайджест усе одно виходить.

Це інваріант 6, і тест на нього стверджує, що клієнт LLM ніколи не викликається, коли стелю було б перевищено. Щотижневий opt-in live-тест (LiveAnthropicCostAndCacheTests, за ключем ANTHROPIC_API_KEY) відправляє matching batch на 20 елементів і стверджує >90% влучань кешу, оцінюючи через той самий CostAccountant.
