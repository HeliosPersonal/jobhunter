The nouns that carry the domain

The objects a Run moves through

TermWhat it is
OwnerThe single human the platform serves — one Telegram chat id, one Keycloak subject. Not a "user": no sign-up, no roles, no tenancy.
ProfileThe Owner's structured career facts (seniority, stacks, salary floor, timezone, countries), derived from the CV plus explicit overrides.
CVOne uploaded document plus its extracted text. Versioned; exactly one version is active. It feeds a Profile — it is not the Profile.
CompanyA hiring organisation, keyed by canonical domain (stripe.com), carrying an ATS binding once detected.
RawPostingThe verbatim payload fetched from a Source, stored immutably with fetch metadata and a content hash. Never edited, only superseded.
JobThe normalised, deduplicated canonical vacancy: title, company, locations, remote policy, type, description, apply URL, timestamps.
FingerprintThe deterministic dedup key: sha256(domain ‖ title ‖ locationSet). Two Jobs with one Fingerprint are one Job.
EnrichmentStage-4 Claude output about the job: salary estimate, remote/contractor flags, timezone, AI-usage, technologies, company stage, reasons.
MatchStage-5 Claude output for a (Job, Profile) pair: score 0–100, missing skills, interview probability, salary expectation, reasons.
ScoreThe final ranking number the Owner sees: f(Match.score, preference weights, freshness). Computed by us, not by Claude.
DigestThe single morning report for one Run: counts, market note, and the ordered list of Cards.
CardOne Job inside a Digest, rendered with its Score, reasons and four actions: Open, Ignore, Save, Applied.
SignalOne recorded Owner action carrying preference information (Opened, Ignored, Saved, Applied, Interview, Offer, Rejected, Rated).
PreferenceModelThe learned, versioned, explainable weights derived from Signals. Every weight must cite the Signals that produced it.
CompanyResearchThe agent-generated dossier for a Company — each claim citing a Source URL.

The execution vocabulary

Run, Batch, ModelTier, CostLedger

A Run is one end-to-end execution of the daily pipeline, with an id, a cost ledger, and — crucially — a resumable state machine. A Batch is one Anthropic Message Batches submission belonging to exactly one Run and one Stage. ModelTier is Cheap (triage/extraction) or Deep (matching/synthesis); the tier→model mapping lives in configuration. The CostLedger accumulates token usage and USD per Stage and Tier, checked against a hard ceiling before each submission.

Run state machine — nine states, resumable, no "Discovering"

Re-running a stage supersedes by (job_id, run_id, stage) — it never duplicates cost or delivery. That is what "resumable" means here.

The rules that always hold

The twelve invariants

These are not aspirations. Most are enforced by a database constraint or an automated test.

1A RawPosting is immutable. Re-fetching produces a new row; it never updates an old one.
2One Fingerprint, one Job. Deduplication merges into the earliest-seen Job and records the alias.
3Every Enrichment and Match belongs to exactly one Job and one Run. Re-running supersedes, never duplicates.
4Every Score is explainable. A Card without at least one reason is invalid and must not be delivered.
5Every CompanyResearch claim cites a URL. An uncited claim is dropped, not shown.
6A Run never exceeds its cost ceiling. The ledger is checked before each Batch submission; exceeding it aborts the stage and marks the Run CostAborted.
7The platform never applies to a job. Applied is a status the Owner sets, not an action the system performs.
8Delivery is idempotent. A (run_id, chat_id, card_key) triple is delivered at most once.
9Single Owner. No registration, no tenant column, no role model.
10Robots and rate limits are respected. A Source failing twice is quarantined, not retried harder.
11Preference learning never hard-filters silently. Every suppression carries a recorded reason, reported in the Digest.
12Secrets never enter the repository, the image layers, or the logs.
The load-bearing one that would be genuinely damaging if broken: the CV crosses exactly one boundary — the Stage-5 match prompt. It appears in no log, no span, no index, no notification, and a sentinel-scan suite verifies it.

Explicitly out of scope

What JobHunter deliberately does not do

  • LinkedIn scraping and aggregator boards (Indeed, Glassdoor, Google Jobs) — brittle, hostile to automation, duplicated and stale.
  • Auto-apply / auto-outreach — invariant 7.
  • Multi-user SaaS — no tenancy, no billing, no onboarding funnel.
  • Mobile app — Telegram is the client. Résumé rewriting is a post-MVP candidate.

Словник виконання

Run, Batch, ModelTier, CostLedger

Run — це одне наскрізне виконання щоденного конвеєра, з id, реєстром вартості та, головне, відновлюваним скінченним автоматом. Batch — одна відправка в Anthropic Message Batches, що належить рівно одному Run і одній Stage. ModelTier — це Cheap (тріаж/екстракція) або Deep (зіставлення/синтез); відповідність tier→model живе в конфігурації. CostLedger накопичує використання токенів і USD за Stage і Tier, перевіряючись проти жорсткої стелі перед кожною відправкою.

Правила, що завжди діють

Дванадцять інваріантів

Це не прагнення. Більшість гарантовані обмеженням бази даних або автоматичним тестом.

1RawPosting незмінний. Повторне отримання створює новий рядок; воно ніколи не оновлює старий.
2Один Fingerprint — одна Job. Дедуплікація зливає в найранішу Job і фіксує аліас.
3Кожен Enrichment і Match належить рівно одній Job та одному Run. Повторний запуск заміщує, не дублює.
4Кожен Score пояснюваний. Card без хоча б однієї причини недійсний і не має доставлятися.
5Кожне твердження CompanyResearch цитує URL. Нецитоване твердження відкидається, а не показується.
6Run ніколи не перевищує стелю вартості. Реєстр перевіряється перед кожною відправкою Batch; перевищення перериває стадію і позначає Run як CostAborted.
7Платформа ніколи не подається на вакансію. Applied — статус, який ставить власник, а не дія системи.
8Доставка ідемпотентна. Трійка (run_id, chat_id, card_key) доставляється щонайбільше раз.
9Єдиний власник. Без реєстрації, стовпця тенанта чи моделі ролей.
10Robots і ліміти швидкості дотримані. Source, що впав двічі, потрапляє в карантин, а не переопитується агресивніше.
11Навчання вподобань ніколи не фільтрує тихо. Кожне придушення несе зафіксовану причину, повідомлену в Digest.
12Секрети ніколи не потрапляють у репозиторій, шари образу чи логи.
Найважливіший, чиє порушення було б справді шкідливим: CV перетинає рівно одну межу — prompt зіставлення стадії 5. Він не з'являється в жодному лозі, span, індексі чи сповіщенні, і це перевіряє sentinel-scan набір.

Явно поза межами

Що JobHunter свідомо не робить

  • Скрапінг LinkedIn та дошки-агрегатори (Indeed, Glassdoor, Google Jobs) — крихкі, ворожі до автоматизації, дубльовані й застарілі.
  • Автоподача / автозвернення — інваріант 7.
  • Мультикористувацький SaaS — без тенантності, білінгу чи онбординг-воронки.
  • Мобільний застосунок — клієнтом є Telegram. Переписування резюме — кандидат на пост-MVP.
