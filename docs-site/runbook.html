Operate it

Deploy & operate

Ship on push to develop through a self-hosted runner into k3s staging (the main → production path is planned, F5-gated); watch it through Grafana Cloud; drive and diagnose it from Telegram; recover from the ten runbooks. Every alert maps to exactly one runbook.

From push to pods

The CI/CD pipeline

GitHub Actions builds and tests on a hosted runner, then a self-hosted helios runner applies Terraform and Kustomize (the k3s API is not publicly reachable). Images go to GHCR tagged by commit SHA; overlays reference the SHA, never :latest.

develop → staging (live); main → production (planned, F5-gated) 
flowchart LR
  push["push / PR"] --> bt["build-and-test
restore · build (warnings=errors) · coverage gate >90% · kustomize render"]
  bt --> img["build-images
matrix Api/Worker/Telegram → GHCR @SHA (lowercased)"]
  bt --> tf["terraform
self-hosted helios · plan/apply"]
  img --> dep["deploy-staging
apply -k overlay · rollout status"]
  tf --> dep
  dep -.->|planned, F5-gated| smoke["main → production + smoke
GET api:8080/health"]
Migrations run as a pre-deploy Kubernetes Job (args: ["migrate"]), never at app startup. The Worker is replicas: 1 with a Recreate strategy — the Hangfire scheduler and Run orchestration are a singleton by design. Only the API is exposed via ingress at jobhunter.devoverflow.org; traffic arrives Internet → Cloudflare → cloudflared tunnel → NGINX.

When something is wrong

The ten runbooks

One runbook per alert; "page" means a Telegram message to the Owner.

IDSituation
R1Digest not delivered by 07:15 — the product did not happen today.
R2Run stuck (non-terminal for > 6 h) — today's digest at risk.
R3Cost ceiling approached or breached — warn at 70%, page on abort.
R4Discovery starved or source failures — includes un-quarantining a source.
R5LLM parse failures above 5% — degraded quality; the Run still completes.
R6Outbox backlog or dead-letter growth — the pipeline stalls silently between stages.
R7Pod restart loop.
R8Typesense index drift — search stale; the digest is unaffected.
R9Restore PostgreSQL from backup — RTO ~30 min.
R10Rotate a credential — Anthropic / Telegram / DB / Keycloak / Infisical.

What you can see

Observability

Every host calls AddServiceDefaults(); traces, logs and metrics go OTLP → Grafana Alloy → Grafana Cloud, correlated by run_id / job_id. The core eight domain instruments live in Telemetry.cs, alongside later feature-specific ones (17 in total):

Metrics

  • jobhunter.run.duration · jobhunter.run.cost_usd
  • jobhunter.jobs.discovered · jobhunter.jobs.deduplicated
  • jobhunter.batch.latency · jobhunter.digest.cards
  • jobhunter.source.failures · jobhunter.llm.parse_failures

Health & labels

  • /alive liveness · /ready (PG+MQ+Redis) · /health (+Typesense, Anthropic, last-Run age)
  • Allowed labels: stage, ats_kind, tier, environment, outcome
  • Forbidden as labels (span-only): job_id, company_id, run_id

Dashboards: Pipeline health, Cost, Quality (precision@10, ignore/save rate, suppression), Infrastructure. /ready must not check Anthropic or Typesense — they are not liveness dependencies.

Driving it by hand

The Telegram command surface

23 commands, asserted a bijection with the CommandRegistry. Sensitive commands need a confirmation tap; ✎ marks a command that changes state. Unknown input is matched by Damerau–Levenshtein (distance ≤ 2 suggests) — never by an LLM.

Digest & search

  • /digest — re-render today's digest (does not re-deliver)
  • /more [n] — next cards below the cut
  • /search <q> — full-text search with tech: stage: country: min: since: filters
  • /hidden — what ranking suppressed, and why

Pipeline

  • /saved · /pipeline · /due — the hiring pipeline
  • /note [text] ✎ — annotate the last-touched application
  • /stats — this week's outcomes and precision@10 trend

Company & profile

  • /company <name> — the dossier; /research <name> ✎ — refresh it
  • /cv — read-only CV metadata (never content, never upload)
  • /prefs — learned weights as sentences; /forget <dim> ✎; /floor <amt> ✎

Operations (sensitive)

  • /status — last Run: outcome, cost vs ceiling, counts
  • /cost [YYYY-MM] — spend by stage/tier vs projection
  • /sources — per-provider health; release a quarantine
  • /run ✎ — start a Run now; /redeliver ✎ — re-send today's digest

Meta: /start, /help [cmd], /cancel. An unauthorised chat receives nothing at all.

Коли щось не так

Десять runbook-ів

Один runbook на алерт; «сповістити» означає Telegram-повідомлення власнику.

IDСитуація
R1Дайджест не доставлено до 07:15 — продукт сьогодні не відбувся.
R2Run застряг (нетермінальний > 6 год) — сьогоднішній дайджест під загрозою.
R3Стелю вартості наближено чи перевищено — попередження на 70%, сповіщення при abort.
R4Discovery виснажено чи збої джерел — включно з виведенням джерела з карантину.
R5Збої парсингу LLM понад 5% — знижена якість; Run усе одно завершується.
R6Затор outbox чи ріст dead-letter — конвеєр тихо застряє між стадіями.
R7Цикл перезапуску пода.
R8Дрейф індексу Typesense — пошук застарілий; дайджест не зачеплено.
R9Відновлення PostgreSQL з бекапу — RTO ~30 хв.
R10Ротація облікового запису — Anthropic / Telegram / DB / Keycloak / Infisical.

Спостережуваність

Кожен хост викликає AddServiceDefaults(); трейси, логи й метрики йдуть OTLP → Grafana Alloy → Grafana Cloud, корельовані за run_id / job_id. Основні вісім доменних інструментів живуть у Telemetry.cs, поряд із пізнішими інструментами для окремих функцій (усього 17):

Метрики

  • jobhunter.run.duration · jobhunter.run.cost_usd
  • jobhunter.jobs.discovered · jobhunter.jobs.deduplicated
  • jobhunter.batch.latency · jobhunter.digest.cards
  • jobhunter.source.failures · jobhunter.llm.parse_failures

Здоров'я й мітки

  • /alive liveness · /ready (PG+MQ+Redis) · /health (+Typesense, Anthropic, вік останнього Run)
  • Дозволені мітки: stage, ats_kind, tier, environment, outcome
  • Заборонені як мітки (лише span): job_id, company_id, run_id

Дашборди: Pipeline health, Cost, Quality (precision@10, частка ignore/save, придушення), Infrastructure. /ready не має перевіряти Anthropic чи Typesense — вони не є залежностями liveness.

Керування вручну

Набір команд Telegram

23 команди, стверджена бієкція з CommandRegistry. Чутливі команди потребують підтверджувального дотику; ✎ позначає команду, що змінює стан. Невідомий ввід зіставляється за Damerau–Levenshtein (відстань ≤ 2 пропонує) — ніколи LLM.

Дайджест і пошук

  • /digest — перерендерити дайджест дня (не переставляє)
  • /more [n] — наступні картки нижче межі
  • /search <q> — повнотекстовий пошук із фільтрами tech: stage: country: min: since:
  • /hidden — що ранжування придушило і чому

Конвеєр

  • /saved · /pipeline · /due — конвеєр найму
  • /note [текст] ✎ — нотатка до останньої заявки
  • /stats — цьотижневі результати й тренд precision@10

Компанія й профіль

  • /company <назва> — досьє; /research <назва> ✎ — оновити його
  • /cv — метадані CV лише для читання (ніколи вміст, ніколи завантаження)
  • /prefs — вивчені ваги як речення; /forget <dim> ✎; /floor <сума> ✎

Операції (чутливі)

  • /status — останній Run: результат, вартість vs стеля, підрахунки
  • /cost [YYYY-MM] — витрати за стадією/ярусом vs прогноз
  • /sources — здоров'я провайдерів; звільнити з карантину
  • /run ✎ — запустити Run зараз; /redeliver ✎ — переслати дайджест дня

Мета: /start, /help [cmd], /cancel. Неавторизований чат не отримує нічого взагалі.
