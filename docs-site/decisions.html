How it is built

Decisions & features

Fifteen accepted Architecture Decision Records fix the stack; eleven features (F0–F10) build on it, each past a docs-first readiness gate before any code. Nothing here is provisional.

The stack, decided

Fifteen accepted ADRs

ADRDecision
0001Modular monolith, three deployables, nine stages. One repo split into three deployables over durable message boundaries, not in-process calls.
0002RabbitMQ transport, Wolverine handlers. Reuse the existing broker; Wolverine handlers with its transactional outbox.
0003PostgreSQL single store; EF Core writes, Dapper reads. EF Core owns migrations and aggregate writes; Dapper owns read models and never writes.
0004Hangfire for scheduling, over Quartz.NET. Durable scheduling on PostgreSQL under a hangfire schema.
0005Anthropic Message Batches API, two-tier cascade. The ~50%-cheaper Batches API with a Cheap tier for extraction and a Deep tier for judgement.
0006Schema-bound structured output, tolerant parsing. Validate every field against a versioned schema; one bad item of 150 never fails the Run.
0007EF Core transactional outbox. Atomic state-change + event publication — no duplicate spend, no duplicate delivery.
0008Typesense over PostgreSQL FTS. Facets and typo tolerance from a rebuildable projection.
0009ATS-first; LinkedIn and aggregators out of scope. Ingest only documented ATS JSON endpoints; no scraping.
0010Kustomize + GHCR + self-hosted runner. Kustomize overlays, GHCR images, a self-hosted Actions runner so the k3s API stays private.
0011Infisical for runtime secrets. Machine-identity Infisical for secrets; a Terraform-produced ConfigMap for non-secret config.
0012OTLP → Grafana Alloy → Grafana Cloud. All traces, logs and metrics correlated by run_id / job_id.
0013.NET Aspire for local dev only. Aspire orchestrates the dev environment; production stays Kustomize.
0014Keycloak OIDC for the API; chat-id allowlist for the bot. Default-deny API scopes; the bot authorises by Telegram chat id.
0015UUID v7 keys, timestamptz UTC, numeric money. Time-ordered keys, UTC timestamps, exact decimal money.

What gets built on top

The eleven features

Each feature is a folder of PRD, SAD, data model and test plan, accepted before the first task. Every task is one reviewable PR of ≤ 500 lines.

FeatureDelivers
F0 · Platform FoundationThe scaffolding: solution/layers, database, bus, scheduler, telemetry, images, deploy pipeline. No user-visible behaviour, deliberately.
F1 · ATS Job DiscoveryCompany registry, ATS detection, polite 6-hour board fetches, immutable RawPosting storage.
F2 · Normalization & DeduplicationRaw payloads → canonical Job; the same vacancy across boards collapses into one. The dedup corpus: zero false merges or the build fails.
F3 · Claude Batch EnrichmentThe engine room: the resumable Run state machine and Batch lifecycle, producing an Enrichment per job. The crash matrix: eight kill points.
F4 · CV Matching & RankingFit, why, gaps, interview probability; the single ordering number. The CV-leakage scan and the golden ranking set.
F5 · Daily Digest & Telegram DeliveryThe product: one 07:00 message plus scannable cards with one-tap actions. First shippable release.
F6 · Application TrackingThe hiring pipeline as a first-class object: seven statuses, history, notes, stale reminders.
F7 · Preference LearningEvery Ignore/Save/Applied outcome becomes weights that reorder tomorrow — and a sentence the digest says out loud.
F8 · Company Research AgentAuto-research of top companies with a URL beside every claim. The uncited-claim and SSRF suites.
F9 · Search & Public APITypesense search with typo tolerance and facets, exposed via a Keycloak-protected HTTP API.
F10 · Telegram Command InterfaceThe pull side: 23 commands to search, work the pipeline, read dossiers, inspect learning and trigger re-runs.

The named suites

Tests that carry a feature's credibility

  • F2 — the dedup corpus: zero false merges, or the build fails.
  • F3 — the crash matrix: eight kill points, each asserting exactly one batch submission.
  • F4 — the CV-leakage scan (sentinel tokens, no allowlist) and the golden ranking set.
  • F5 — the rendering corpus and the duplicate-delivery suite.
  • F7 — the synthetic-behaviour corpus, including the indifferent profile that must produce no weights.
  • F8 — the uncited-claim and SSRF suites.
  • F9 — the index scan, rebuild equivalence and endpoint-convention suites.
Coverage must stay above 90% (line and branch), CI-enforced by a dedicated Enforce coverage gate step that merges the per-assembly cobertura reports with ReportGenerator and fails the build below 90% line or branch. (The Coverlet MSBuild threshold in tests/Directory.Build.props is a local-only convenience; CI collects coverage via --collect:"XPlat Code Coverage".) Excluded via coverage.runsettings: the Aspire AppHost, ServiceDefaults, Contracts and TestKit, all migrations, and any [ExcludeFromCodeCoverage] type — which is how the three host Program.cs roots are excluded.

Як це побудовано

Рішення й функції

П'ятнадцять прийнятих Architecture Decision Records фіксують стек; одинадцять функцій (F0–F10) будуються на ньому, кожна пройшла docs-first-ворота готовності до будь-якого коду. Тут немає нічого тимчасового.

Стек, вирішено

П'ятнадцять прийнятих ADR

ADRРішення
0001Модульний моноліт, три розгортання, дев'ять стадій. Один репозиторій, розділений на три розгортання через довговічні межі повідомлень, не внутрішньопроцесні виклики.
0002Транспорт RabbitMQ, обробники Wolverine. Повторне використання наявного брокера; обробники Wolverine з його транзакційним outbox.
0003PostgreSQL — єдине сховище; EF Core пише, Dapper читає. EF Core володіє міграціями й записами; Dapper володіє моделями читання і ніколи не пише.
0004Hangfire для планування, замість Quartz.NET. Довговічне планування на PostgreSQL у схемі hangfire.
0005Anthropic Message Batches API, двоярусний каскад. На ~50% дешевший Batches API з ярусом Cheap для екстракції та Deep для судження.
0006Структурований вивід за схемою, толерантний парсинг. Кожне поле валідується проти версіонованої схеми; один поганий елемент зі 150 ніколи не валить Run.
0007Транзакційний outbox EF Core. Атомарна зміна стану + публікація події — без подвійних витрат і подвійної доставки.
0008Typesense замість PostgreSQL FTS. Фасети й толерантність до одруківок із перебудовуваної проєкції.
0009ATS-first; LinkedIn та агрегатори поза межами. Приймати лише документовані ATS JSON-ендпойнти; без скрапінгу.
0010Kustomize + GHCR + self-hosted runner. Overlays Kustomize, образи GHCR, self-hosted Actions runner, щоб API k3s лишався приватним.
0011Infisical для runtime-секретів. Infisical із machine-identity для секретів; ConfigMap із Terraform для несекретної конфігурації.
0012OTLP → Grafana Alloy → Grafana Cloud. Усі трейси, логи й метрики корельовані за run_id / job_id.
0013.NET Aspire лише для локальної розробки. Aspire оркеструє dev-середовище; продакшн лишається на Kustomize.
0014Keycloak OIDC для API; allowlist chat-id для бота. Default-deny скоупи API; бот авторизує за Telegram chat id.
0015Ключі UUID v7, timestamptz UTC, numeric для грошей. Впорядковані в часі ключі, UTC-мітки, точні десяткові гроші.

Що будується згори

Одинадцять функцій

Кожна функція — це тека з PRD, SAD, моделлю даних і тест-планом, прийнятими до першого завдання. Кожне завдання — один PR на ≤ 500 рядків.

ФункціяЩо дає
F0 · Platform FoundationКаркас: рішення/шари, база, шина, планувальник, телеметрія, образи, деплой-конвеєр. Свідомо без видимої поведінки.
F1 · ATS Job DiscoveryРеєстр компаній, виявлення ATS, ввічливі 6-годинні опитування дошок, незмінне зберігання RawPosting.
F2 · Normalization & DeduplicationСирі payload-и → канонічна Job; та сама вакансія на різних дошках зливається в одну. Дедуп-корпус: нуль хибних злиттів або білд падає.
F3 · Claude Batch EnrichmentДвигун: відновлюваний автомат Run і життєвий цикл Batch, що дає Enrichment на вакансію. Crash-матриця: вісім точок збою.
F4 · CV Matching & RankingВідповідність, чому, прогалини, імовірність співбесіди; єдине число впорядкування. Скан витоку CV і золотий набір ранжування.
F5 · Daily Digest & Telegram DeliveryПродукт: одне повідомлення о 07:00 плюс скановані картки з діями в один дотик. Перший придатний до випуску реліз.
F6 · Application TrackingКонвеєр найму як першокласний об'єкт: сім статусів, історія, нотатки, нагадування про застій.
F7 · Preference LearningКожен результат Ignore/Save/Applied стає вагами, що переставляють завтра — і реченням, яке дайджест промовляє вголос.
F8 · Company Research AgentАвтодослідження топ-компаній з URL біля кожного твердження. Набори uncited-claim та SSRF.
F9 · Search & Public APIПошук Typesense із толерантністю до одруківок і фасетами, доступний через HTTP API під захистом Keycloak.
F10 · Telegram Command InterfaceСторона витягування: 23 команди для пошуку, роботи з конвеєром, читання досьє, інспекції навчання й запуску повторів.

Іменовані набори

Тести, що несуть довіру до функції

  • F2 — дедуп-корпус: нуль хибних злиттів, або білд падає.
  • F3 — crash-матриця: вісім точок збою, кожна стверджує рівно одну відправку batch.
  • F4 — скан витоку CV (sentinel-токени, без allowlist) і золотий набір ранжування.
  • F5 — корпус рендерингу і набір подвійної доставки.
  • F7 — корпус синтетичної поведінки, включно з байдужим профілем, що має дати нуль ваг.
  • F8 — набори uncited-claim та SSRF.
  • F9 — набори index scan, rebuild equivalence та endpoint-convention.
Покриття має лишатися вище 90% (рядки й гілки), гарантовано в CI окремим кроком Enforce coverage gate, що зливає покриття по збірках через ReportGenerator і валить збірку нижче 90% за рядками чи гілками. (Поріг Coverlet у tests/Directory.Build.props — лише локальна зручність; CI збирає покриття через --collect:"XPlat Code Coverage".) Виключені через coverage.runsettings: Aspire AppHost, ServiceDefaults, Contracts і TestKit, усі міграції та будь-який тип із [ExcludeFromCodeCoverage] — саме так виключені три хостові корені Program.cs.
